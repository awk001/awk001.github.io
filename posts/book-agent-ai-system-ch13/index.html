第 13 章是第一个综合案例，把前面学的”范式 + 工具 + 协议 + 多智能体”一次性用起来：做一个能规划行程、订票、查天气的旅行助手。

13.1 需求拆解

一个合格的旅行助手要能：

  1. 理解自然语言的需求（”国庆去成都玩 4 天，喜欢美食和博物馆”）；
  2. 规划行程（第 4 章 Plan-and-Solve）；
  3. 调用多个工具：搜索、地图、天气、票务（第 10 章 MCP）；
  4. 多角色协作：规划师 / 预订师 / 审核师（第 6 章多 Agent）。

13.3 用 MCP 接工具的好处

把”查天气””查地图””查票价”都做成 MCP Server 后，旅行助手只需面向统一协议调用，新增一个能力（如”订餐厅”）只是起一个新 Server，不动主逻辑——这正是第 10 章讲的价值。

13.4 关键实现点

  • 规划与执行分离：先出完整计划，再逐条执行，避免边想边改导致混乱；
  • 工具结果校验：票价/余票可能为空或过期，要做空值与异常兜底；
  • 用户确认节点：涉及”下单”的动作加 human-in-the-loop，防止误操作。

13.5 常见坑

  • 工具返回过长，撑爆上下文 → 用第 9 章的上下文工程做裁剪；
  • 多 Agent 互相甩锅 → 明确每个角色的输入输出契约；
  • 只信模型编的”票价” → 一切以工具真实返回为准。

13.6 小结

旅行助手是”多工具 + 多 Agent”的教科书级案例。它验证了：协议让工具即插即用，规划/执行分离让流程可控。下一章我们做一个更”重研究”的 Agent——自动化深度研究。
