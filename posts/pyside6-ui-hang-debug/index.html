界面偶尔卡一下，测试的时候偶现，开发者本机完全复现不了。这种问题最耗人。

先排除错误的方向

遇到卡顿，第一反应往往是「加点 sleep 让它等等」。这是最坏的开端。

这不解决任何问题，只是把概率性的时序冲突变成稳定复现。真正的竞态还在那里，只是被推迟了，日后会在更难查的地方冒出来。

这一步抓到的问题在：设备数据采集的回调里，触发了 UI 线程的同步刷新。

根因

回调可能在工作线程上被触发，也可能被 QMetaObject.invokeMethod 切回主线程。两条路径都会走到同一个刷新函数，而其中一条是重入的。

教训

  1. 偶发问题看分布，不看单次。 单次日志只能证明「这次没问题」。
  2. 不要用 sleep 掩盖时序问题。 它把问题藏起来，不是修掉。
  3. 线程归属要在入口统一，不要在每一处判断。 分散的 if 判断迟早会漏一处。
