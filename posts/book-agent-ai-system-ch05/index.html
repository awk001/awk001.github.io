第 5 章转向”不写代码也能搭 Agent”。对想快速验证想法、或没有工程团队的业务方，低代码平台是把第 4 章范式”拖拽化”的最佳入口。

5.1 为什么先讲低代码

  • 跑通闭环最快：拖一个节点、连一条线，几分钟看到 Agent 跑起来；
  • 隐藏工程细节：编排、上下文管理、工具接入都被平台封装；
  • 适合原型与业务编排：非算法同学也能参与。

要点：低代码平台的价值不是”取代写代码”，而是让你在不懂全部底层时也能快速验证业务假设。

5.2 三个代表平台（思路对比）

平台 强项 适合场景
Coze 对话 Bot、插件市场、多渠道发布 客服 / 社群机器人
Dify 工作流 + 知识库 + 可视化，偏开发者 企业内部知识助手
n8n 通用自动化编排，节点极多 跨系统流程自动化

5.3 一个通用的低代码 Agent 结构

不论哪个平台，本质都是这几块：

  1. 触发器：用户消息 / 定时 / Webhook；
  2. 大模型节点：承载推理（对应 ReAct 的 Thought）；
  3. 工具 / 插件节点：搜索、数据库、API 调用（对应 Act）；
  4. 知识库节点：RAG 检索（第 8 章详述）；
  5. 记忆节点：会话上下文保持。

5.4 实战建议

  • 先用平台的模板改，而不是从空白建；
  • 把”提示词”当成产品文案来打磨，它直接决定体验；
  • 复杂逻辑别硬塞进一个 Bot，拆成多个 Agent 再用工作流串。

5.5 低代码的边界

当你需要自定义工具协议、精细控制循环、私有化部署、复杂多智能体协作时，就到了该切到代码框架（第 6 章）的时机。

5.6 小结

低代码平台把范式”可视化”，适合原型与业务编排；但一旦要深度定制，就得回到代码。下一章我们进入三大主流框架，看工程化是怎么做的。
