五层记忆体系与 CLAUDE.md 写作范式，含典型项目配置实战。

2.1 为什么记忆是 Agent 的瓶颈

大模型的上下文窗口有限，而真实项目的代码量远超窗口容量。记忆系统的作用不是「记住一切」，而是「在合适的时间把合适的信息放到窗口里」。

没有记忆系统的 Agent 会在多轮对话后反复问同一个问题，或者在修改文件时忘记刚刚达成的约定。记忆系统让 Agent 的行为从「单次即兴」变成「持续一致」。

2.2 五层记忆体系

本书把记忆分为会话记忆、工作区记忆、项目记忆、领域记忆和组织记忆。会话记忆处理当前对话；工作区记忆管理本次任务上下文；项目记忆沉淀项目规范；领域记忆保存通用工程原则；组织记忆则维护跨项目的最佳实践。

这五层对应不同的时间尺度与更新频率。越靠近会话层，变化越快；越靠近组织层，越稳定、越需要人工审核。

2.3 CLAUDE.md 写作范式

CLAUDE.md 是项目记忆的核心载体。好的 CLAUDE.md 不是文档大全，而是「决策捷径」：它告诉 Agent 在这个项目里怎么做对、怎么避免常见错误。

写作时建议遵循「条件化规则」：当遇到 X 情况时，采取 Y 动作。例如「当修改路由时，同步更新 tests/test_routes.py」。规则越具体，Agent 的执行越稳定。

2.4 项目配置示例

React 项目：在 CLAUDE.md 中约定组件目录结构、测试文件位置、样式命名规则。

Node 项目：明确 package.json 脚本用法、错误处理模式、日志规范。

Python 项目：约定虚拟环境、类型注解覆盖率、依赖管理方式。

2.5 小结

记忆系统让 Agent 拥有持续一致的行为能力。CLAUDE.md 是项目记忆的入口，写得具体、条件化，比写得全面更重要。
