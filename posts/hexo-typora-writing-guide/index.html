用 Typora 写 Markdown 并发布到 Hexo 博客：规范与避坑

本文档整理自日常写作流程，目标只有一句话：用 Typora 顺畅地写，写完一键发到公网，不踩重复踩过的坑。

下面的示例均基于本博客的技术栈：Hexo 7 + async 主题，托管在 GitHub Pages（awk001.github.io）。

二、文章头（Front Matter）模板

每篇文章开头必须有一段 --- 包裹的元数据。直接复制下面的模板，改掉对应字段即可：

要点：

  • published: true 必写。想先存草稿把它改成 false，本地用 npm run dev -- --drafts 才能预览。
  • categories / tags 都是数组写法（方括号 + 引号），不要写成纯字符串。
  • author 不写会回退到站点全局作者（当前为「悠悠」），但建议每篇显式写上。

三、正文写作约定

  • 摘要截断：在正文里想让首页列表只显示到某处，加一行 <!-- more -->，它之前的内容进列表摘要，之后内容进详情页。

  • 代码块务必指定语言：用 ```语言 并写明语言（如 python / bash / js），主题才会正确高亮上色。

  • 标题：正常用 # / ##，Hexo 会自动生成锚点，不要手写 <a>。

四、图片（截图）怎么处理

博客已开启 post_asset_folder + marked.postAsset，采用图片随站点自托管方案，不依赖任何第三方图床。

Typora 只需设置一次（中文界面）：

  1. 文件 → 偏好设置 → 左侧「图像」
  2. 「插入图片时…」选择 复制到指定路径，路径框填：./${filename}
    • ⚠️ 关键：把默认带的 .assets 后缀去掉，只留 ${filename}，才能和 Hexo 的同名资源文件夹对齐
  3. 勾选「对本地图片应用上述规则」
  4. 勾选「优先使用相对路径」

之后写文章时直接 Ctrl+V 粘贴截图，Typora 会自动把图片存到：

正文里生成的是相对引用 ![](截图.png)。Hexo 构建时会自动把图片发布到正确地址，Typora 本地预览和公网显示两边都能正常工作。

备选方案：如果你更习惯用图床（如 SM.MS，或自己的对象存储 + PicGo），在 Typora 图像设置里选择「上传图片」并配好 PicGo 即可，正文里是 https 链接，无需关心路径。但图床有外链可用性风险，默认推荐上面的本地自托管。

六、常见坑（已踩过，记在此处）

现象 原因 处理
文章完全不发布，构建也不报错 文件名 _ 开头被 Hexo 当私有文件忽略 改名去掉前导下划线
改了 .less 样式没生效 npm run build 不会重编译改动过的 LESS 先 npm run clean 再 npm run build
公网看不到刚发的文章/改动 GitHub Pages 边缘缓存最终一致性 等 1–3 分钟，或浏览器 Ctrl+Shift+R 强刷
相对路径图片 404 资源文件夹机制未开启（现已开启） 用上面 Typora 同名文件夹方案
菜单选中项没有下划线 旧版 active 判断逻辑写死不成立 已改用 is_current()，归档/首页等都会高亮
执行 npm run deploy:manual 报 _ssh: Could not resolve hostname github.com 当前工作区终端的沙箱拦截了到 GitHub 的 SSH 出站（不是真 DNS 故障，nslookup github.com 能正常解析） 由我（agent）这边执行部署；或在本机非沙箱终端用 SSH 部署；若想在本环境自己部署，需把部署地址改为 HTTPS 并配置 GitHub Personal Access Token

以上流程跑通后，写作就是「Typora 写 → 本地预览 → build → deploy」四步，剩下的交给脚本。
