Hexo 博客接入 Twikoo 评论系统（Netlify + MongoDB Atlas 完全免费）

本文记录一个完整的闭环：在一台已有的 Hexo + async 主题博客上，从零把 Twikoo 评论系统跑通，且后端全程零花费。

成品效果：文章底部出现评论框，访客可以留言、管理员可以审核。

一、为什么是这套组合

诉求 选择 理由
评论系统 Twikoo 免费、无广告、界面干净，和 imalun.com 同款
后端存储 MongoDB Atlas（M0 免费集群） 512MB 足够个人博客，永久免费
运行环境 Netlify Functions（免费额度） 官方对免费方案支持最好，每月 12.5 万次请求足够
主题 Hexo + async 原生支持 comment.twikoo.envId，无需改主题文件

方案对比（先看清再动手）

方案 费用 国内访问 备注
Netlify + MongoDB Atlas 0 元 不错 ✅ 本文路线
Vercel + MongoDB Atlas 0 元 慢 / 可能被墙 建议绑自己域名
腾讯云 CloudBase 免费体验版 0 元 快 ❌ 加不了跨域域名，评论框调不通
腾讯云 CloudBase 个人版 19.9 元/月 最快 付费备选，用已建好的函数

结论：想免费就走 Netlify。CloudBase 免费版在「HTTP 网关 - 跨域设置」里会提示”您当前版本暂不支持此功能”，所以免费版配不出来，必须付费。

二、前置条件

  1. 一个已能正常构建、部署的 Hexo 博客（本文基于 awk001.github.io）。
  2. 一个 GitHub 账号（用于 Fork Twikoo 仓库、授权 Netlify）。
  3. 一个能收验证码的邮箱（注册 MongoDB Atlas / Netlify 用）。

三、步骤一：准备 MongoDB Atlas 免费数据库

Twikoo 把评论数据存在 MongoDB。用 Atlas 的免费 M0 集群。

1. 注册并建集群

  1. 打开 MongoDB Atlas ，用 GitHub 或邮箱注册。
  2. 进入控制台，点击 Create → Shared Cluster（M0，免费）。
  3. 云厂商选任意一家（如 AWS），地域选离你近的（如 Singapore）。
  4. 集群名保持默认，点击 Create Cluster。等待 1–3 分钟，状态变 Active。

2. 创建数据库用户

  1. 左侧菜单 Security → Database Access。
  2. 点 Add New Database User。
  3. 认证方式选 Password，用户名填 twikoo，设一个强密码（记下来）。
  4. 权限选 Read and write to any database。
  5. 点 Add User。

3. 放行网络访问（关键）

  1. 左侧菜单 Security → Network Access。
  2. 点 Add IP Address。
  3. 在 Access List Entry 填 0.0.0.0/0（允许所有 IP）。
  4. 点 Confirm。

Netlify 函数的出口 IP 不固定，所以必须放行 0.0.0.0/0，不能只填某个 IP。

四、步骤二：部署 Twikoo 到 Netlify

1. Fork 官方仓库

  1. 打开 github.com/twikoojs/twikoo-netlify。
  2. 点右上角 Fork，确认 fork 到你自己的 GitHub 账号，点 Create fork。
  3. 现在你账号下有了 你的用户名/twikoo-netlify。

你不需要拥有原仓库，Fork 一份到自己账号即可。Netlify 导入的是你 fork 的副本。

2. 导入 Netlify

  1. 打开 app.netlify.com 注册 / 登录。
  2. 点 Add new site → Import an existing project。
  3. 选 Deploy with GitHub（首次会要求授权 GitHub，按提示允许）。
  4. 在仓库列表里选你刚 Fork 的 你的用户名/twikoo-netlify。

3. 配置环境变量（重点）

在部署配置页找到 Environment variables，添加变量：

  • Key：MONGODB_URI
  • Value：你上面保存的连接字符串（密码已替换）
  • 勾选 Contains secret values（保护密码，勾后值会变星号）
  • Values 区域填 Production 那一栏即可（勾了 secret 后不能选 “Same value for all contexts”，只在 Production 填就行）

踩坑：Netlify 勾选 secret 后会强制按部署环境分别填，没有 “Same value” 选项。只填 Production 框，其他留空。你的主站跑的就是 Production。

4. 部署

点 Deploy site，等待状态从 Building 变成 Published。

5. 关闭站点保护（务必做，否则 401）

新站默认是 Private，外部访问函数会被要求登录 Netlify 账号，返回 401，评论框加载不出来。

  1. 进入 Project configuration → General → Visitor access（访客访问）。
  2. 把 Project visibility（项目可见性） 改为 Public。
  3. Deploy Preview 若也是 Private，一并改为 Public。

也可以直接打开 https://app.netlify.com/projects/<站点名>/configuration/general/#project-visibility 改。

6. 重新部署让环境变量生效

加了 MONGODB_URI 之后的那次部署其实是在加变量之前发生的，函数里还没有数据库地址，必须重跑一次：

  1. 左侧菜单 Deploys。
  2. 点最新一条部署右边的 Options → Retry with latest branch commit。
  3. 等状态重新变回 Published。

如果还是空白，按下面的 FAQ 排查。

九、步骤七：管理员后台

Twikoo 部署后首次使用要设置管理员：

  1. 打开带评论的文章页，按 Ctrl + Shift + K（或在评论框右下角找「管理」入口）。
  2. 设置管理员密码、邮箱。
  3. 后台可配置：
    • 评论审核（防垃圾）
    • 邮件通知（新评论推送到邮箱）
    • 反垃圾（Akismet、腾讯云验证码）
    • 微信 / QQ / Telegram 推送

十、踩坑与 FAQ

现象 原因 处理
访问 Netlify 函数返回 401 / 跳登录页 站点可见性还是 Private Project configuration → General → Visitor access → 改 Public
函数已部署但连不上数据库 加变量前的旧部署缓存 Deploys → Retry with latest branch commit 重新部署
评论框空白，控制台报 envId 错误 envId 未填或填错 Netlify 必须是完整 URL（带 /.netlify/functions/twikoo），不是根域名
显示「Twikoo 加载失败」 函数未公开 / MongoDB 网络未放行 确认 visibility=Public、MongoDB Network Access=0.0.0.0/0
GitHub Releases 找不到 twikoo-cloudbase.zip Twikoo 已改在线 npm 安装 CloudBase 方案直接写 index.js+package.json，不下载任何文件
填 secret 后不能选 “Same value” Netlify 限制 只在 Production 框填连接字符串，其他留空
本地预览看不到评论 Twikoo 需要真实域名 localhost 可显示但功能受限，最终以公网为准

十一、关键约定速查

  • 评论系统：Twikoo
  • 免费后端：Netlify Functions + MongoDB Atlas M0
  • 主题配置字段：_config.async.yml 的 comment.twikoo.envId
  • envId 形式：Netlify 是完整 URL，CloudBase 是 env-xxx
  • 文章关评论：front matter 加 comments: false
  • 管理后台：Ctrl + Shift + K
  • 部署命令：npm run clean && npm run build && npm run deploy:manual

照以上步骤拿到 Netlify 函数 URL 并填好 envId，博客就有了和 imalun 一样的评论功能，且后端每月零花费。
